# ICLE × Jev：轻量潜力验证

本轮已完成：20 个合成场景，18 次真实 Jev `jev-1.13.0` 推断，0 次重试。任务执行、权限授予、真实经验库写入、消息发送和部署均未发生；ICLE 业务源码没有修改。

结论：**相似经历重排序与未知/冲突失败分类值得优先试点；任务画像可以生成结构化提议，但工具需求判断和复核覆盖率仍需改进。**

## 测试设计

- 8 个画像场景：6 个明确任务，1 个缺上下文请求，1 个问候。
- 6 组经历排序：5 组有相关候选，1 组全部无关，每组 3 个候选。
- 6 个失败场景：明确认证失败和已成功恢复的运行直接使用现有规则；另外 4 例 unknown 或类别冲突才调用 Jev。
- 调用前冻结输入、标签、题目、门禁和模型版本；预期标签未发送给 Jev。
- 数据由助手根据现有合同构造并标注，不是独立人工盲测集。候选包含词面干扰与直接匹配控制例，不能当作真实工作负载分布。
- 使用 Choice 处理有限类别，Noul 处理工具需求和候选相关性；不要求 Jev 生成计划、解释或执行代码。

## 1. 任务画像

| 检查 | 结果 |
|---|---:|
| 就绪/需澄清/无任务 | 8/8 |
| 6 个明确任务的已标注字段 | 35/36 |
| 已标注字段完全匹配的任务 | 5/6 |
| 通过 ICLE 原有 TaskProfile 校验 | 6/6 |
| 门禁允许直接展示画像提议 | 2/6 |
| 缺上下文与无任务被阻断 | 2/2 |

评分字段是 readiness、primary_type、subtype、difficulty、risk、工具集合。context_requirement、estimated_duration、decomposition、review 也返回并接受现有格式校验，但没有参考标签，**不计入上述准确率**。格式通过不等于判断正确。

观察：

- 单步生产发布被识别为 **D1 + R3**，没有把高风险自动等同于高难度。
- 跨模块公共 API 修改被识别为 **D4 + R2**。
- “只读文件查看器检查 CSV，禁止写脚本、执行命令”仍得到 `shell=0.54`，按预定 0.5 阈值产生多余工具建议。该例被复核门禁拦截，未执行任何命令。
- 正确的仓库调试和重构场景中，`mcp=0.43` 导致复核；单步生产操作中 `filesystem=0.48`、`shell=0.68` 也导致复核。门禁只自动放行两个纯文本/代码片段场景，覆盖率为 33.3%。不能只展示已放行样本正确率。

接口适配：代码把 Jev 的有限答案组装为现有 TaskProfile，并调用 `skills/task-intelligence/scripts/validate_profile.py`。必需的 reason 使用清楚标记的代码模板生成，没有伪造模型自由文本解释。

门禁在调用前固定：readiness 所选概率 ≥0.7，primary/risk ≥0.75，difficulty ≥0.6，实际使用的 subtype ≥0.6；工具概率落在 (0.3,0.7) 内需复核。未选任务类型的猜测性 subtype 不参与门禁。UNKNOWN 不强制转换为正常画像。

## 2. 相似经历重排序

基线直接调用 ICLE 的 `similar_episodes`（词集合 Jaccard）；Jev 使用完整候选任务文本，独立判断每个候选是否解决同一核心问题，再由代码排序。

| 场景 | 当前关键词基线 | Jev |
|---|---|---|
| 重复扣款 → 幂等请求 | 首位错误 | 首位正确 |
| 搜索慢 → 索引与执行计划 | 首位错误 | 首位正确 |
| 语气友好 → 保持含义的礼貌改写 | 首位错误 | 首位正确 |
| CSV BOM 直接匹配控制例 | 首位正确 | 首位正确 |
| 登录令牌测试直接匹配控制例 | 首位正确 | 首位正确 |
| 机械磨损问题、候选全是软件/文案 | 基线只返回排序，不支持拒选 | Jev 拒选 |

有匹配候选的 5 组中，首位命中 **2/5 → 5/5**；全部不匹配的 1 组正确拒选。预设选择条件：最高 Noul ≥0.6，且比第二名高至少 0.15。

这是**候选集合已包含相关经历**时的排序潜力，不验证大规模检索召回。关键词重叠干扰是主动构造的，不能将这次提升外推为真实使用中的固定提升。

## 3. 规则 + Jev 失败分类

基线直接调用 ICLE `analyze_failure`。明确单一规则继续使用规则，unknown 或多个规则同时命中才由 Jev 提议主因；所选概率不足 0.7 时保留 unknown。

| 场景 | 现有规则 | 混合结果 |
|---|---|---|
| 明确 HTTP 401 | auth | auth，未调用 Jev |
| 曾超时但最后成功 | not_a_failure | not_a_failure，未调用 Jev |
| 中文“目标主机拒绝连接” | unknown | network |
| 中文“存储空间耗尽” | unknown | environment |
| login/network 成功，但断言失败 | auth + test_failure + network | test_failure |
| 退出码 1，无其他日志 | unknown | unknown |

与预设原因集合完全吻合 **3/6 → 6/6**，新增 4 次 Jev 调用。它改善了中文表达和“日志提到某类事情但并未失败”的识别；保留 unknown 的案例没有被强行归因。所有结果仍是待验证的分类提议。

## 建议接入顺序

1. **相似经历重排序**：先保留本地粗检索，让 Jev 判断小批候选的适用性；无合适候选时允许空结果。
2. **失败分类兜底**：保留低成本确定性规则，Jev 只处理 unknown 或规则冲突。
3. **任务画像提议**：保留用户复核。先由代码提供实际可用工具与明确约束，再判断需求；工具建议不能直接变成执行权限。

本轮没有证明真实 Agent 执行成功率、长期调度收益或总体准确率，也未测试自由文本规划、结果 Judge 或长会话重建。
